# ai-berkshire 移植 · 子项目 B：决策纪律 Skill + Worker 纪律句 — Design

> 让监控分析强制输出可执行结论（而非「一方面…另一方面…」的中性平衡），关键决策含分层建议（激进/稳健/保守）。
> 灵感源自 ai-berkshire 的「镜子测试」与「分层建议」框架（README "为什么不能直接问 AI" 一节）。

## 背景与动机

LLM 默认倾向于两面讨好的「balanced analysis」，对单人投资者价值极低 — 我每天看到的是「PDD 有增长潜力但也面临竞争压力，需要权衡」这种文本，无法据此做决策。

ai-berkshire 框架的核心产品差异之一就是**强制结论 + 分层建议**：
- 镜子测试：5 句话说不完整 = 不买
- 分层建议：激进型在 $95-105 建仓；稳健型等回购明确；保守型不达 10 年确定性，观望

这套纪律可以被双重落地到 trader：
1. 作为可选 skill，让纪律意识强的用户挂载
2. 作为 worker 主 prompt 的全局纪律句，对所有 monitoring run 生效（但不强制改 output schema）

### 决策日志

| 决策点 | 选择 | 替代方案 | 理由 |
|---|---|---|---|
| 落地方式 | Skill + worker 全局纪律句 | 仅 Skill / 仅 prompt / 改 schema | 双管齐下：skill 是详细方法论卡片，prompt 是默认底线；不动 schema 避免改 UI |
| 纪律句强度 | 强制行为 + 鼓励行为分开 | 全强制 | 「无规则不编造」「建议必含具体数字」是硬要求；「分激进/稳健/保守」是鼓励，避免日常分析过度仪式化 |
| 写哪个 prompt | `analyze.ts` 主 user 消息末尾 | 移到 system prompt | 现 worker 没用 system prompt，全在 user 消息；保持一致 |
| 输出格式 | 与现有三段式（结论/操作/...）对齐 | 引入新段落 | 现有三段式已经基本是「强制结论 + 操作清单」框架，纪律句只需收紧措辞 |

```markdown
# 决策纪律

> 改写自 ai-berkshire 框架的核心差异点。本 skill 用于压住 LLM 默认倾向 — 给可执行结论而非两面讨好的分析。

## 一、镜子测试

把你对这笔买入的理由写下来。如果 5 句话说不完整，或者写的时候觉得心虚，**这次就不买**。镜子测试不解决「买什么」，只解决「不买什么」。

不通过镜子测试的特征：
- 理由里出现「也许」「可能」「应该会」三次以上
- 5 句话里有 2 句以上是「但是…」结构
- 把价格走势作为主要理由（「最近跌了所以可以买」）
- 无法用一句话说清「10 年后这家公司在做什么」

## 二、分层建议

当给出 buy 建议时，按风险偏好分三档输出（**仅当主结论是 buy 时启用**；hold/sell 时不需要）：

| 档位 | 触发条件 | 价格区间 / 仓位 |
|---|---|---|
| 激进型 | 当前价已在心理价位区间 | 具体股数 / 金额 |
| 稳健型 | 等某个事件兑现（财报、政策、估值回调）再建仓 | 触发条件 + 价格 |
| 保守型 | 不符合 10 年确定性 / 数据不足 | 观望，不动 |

## 三、灰色地带处理

「数据不足」**不等于**「不通过」，也**不等于**「通过」 — 诚实标注为「灰色地带，需补充一手信息」。

LLM 容易把「资料少」误判为「看不懂」。但「看不懂」有两种：生意太复杂真的看不懂、你还没花时间去看。前者放弃，后者补研究 — 两种都不要硬填表格。

## 四、输出格式提醒

每次分析必须满足：

- 结论是一句完整中文句子（不是「需要权衡」「请自行判断」）
- 有操作建议时含具体股数 / 金额 / 价位（数字不出现 = 等于没建议）
- 无规则触发时**只写「无需操作」一行**，不要为了凑字数编造观察
```

## prompt 改动

`apps/worker/src/monitoring/analyze.ts` 在现有主 user 消息（约 line 136-170）的「请按下面三段式结构写 analysis 字段」段落之后，追加以下中文纪律句（一段，不分小节）：

```text

## 决策纪律（适用于所有分析）

- **必须给结论**：每段开头一句话给出今天的判断，不要「一方面…另一方面…」式的中性平衡
- **建议必含数字**：若给买入/卖出/调仓建议，必须包含具体股数、金额或价位；数字不出现 = 等于没建议
- **无规则不编造**：未触发任何策略规则时，仅写「无需操作」一行，不要为了凑字数硬编观察
- **数据不足时诚实标注**：缺关键数据时写「数据不足无法判断」，不要硬填
- **首次买入信号触发时**，鼓励（非强制）按激进型 / 稳健型 / 保守型 三档给价位区间
```

实现细节：

```ts
// 在 analyze.ts 主消息字符串拼接里
const disciplineBlock = `
## 决策纪律（适用于所有分析）
- ...（上述 5 条）
`;

// 拼接在「请按下面三段式结构」段之后、tool call 触发之前
```

## 测试策略

1. **prompt 包含纪律句**：mock anthropic client，断言 `messages[0].content` 包含「必须给结论」「建议必含数字」「无规则不编造」三个关键短语
2. **现有三段式测试不破**：跑 `analyze.test.ts` 现有 case，三段式结构（结论 / 操作 / ...）仍工作
3. **手动验收**：本地跑一次 monitoring，对比新旧 analysis 文本，验证：
   - hold 状态下不再有「观察 / 等待 / 跟踪」一类填充语
   - buy 信号触发时含具体股数
4. **skill 加载测试**：与子项目 A 共享 — 确认 decision-discipline.md 能被 seed manifest 解析

## 风险与开放问题

| 风险 | 影响 | 应对 |
|---|---|---|
| LLM 过度自信，把灰色地带也强行结论化 | 中 | skill 第 3 节明确「数据不足 ≠ 通过/不通过」；prompt 第 4 条强化 |
| 三段式 + 纪律句 prompt 变长，token 成本上升 | 低 | 纪律句约 200 tokens，可忽略 |
| 鼓励的「分层建议」未生效（LLM 忽略鼓励级要求） | 低 | 接受 — 鼓励级本就不强制；如长期未触发可后续升级 |
| skill 与 prompt 重复（挂了 skill 的策略会收到两份纪律内容） | 低 | 接受 — 加强而非冲突；如有干扰再调整 |
