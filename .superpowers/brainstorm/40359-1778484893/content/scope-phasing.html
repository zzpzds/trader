项目规模评估：全部一次构建 vs 分阶段？

这是最重要的可行性决策。四个模块的复杂度差异很大。

模块 ①
AI 策略构建
对话 UI + Claude API + 策略 DSL
复杂度：中
难点：策略 DSL 表达力 vs 简洁性的平衡
模块 ②
回测引擎
OHLCV + 指标计算 + 仓位模拟
复杂度：高
难点：多时间框架、指标精确性、手续费模型
模块 ③
贝叶斯优化器
GP + EI + 参数搜索
复杂度：高
难点：TS 生态缺乏现成库，需手动实现 GP
模块 ④
持仓管理
模拟仓/实仓 + 信号监控 + 通知
复杂度：低
无券商 API，主要是数据 CRUD + 轮询

三种构建策略，选哪一种？

A

全量构建（一次性）

四个模块同时设计、同时实现

优点

  • 系统完整，上线即可用
  • 接口提前设计，避免返工

风险

  • 工作量大，容易失去动力
  • 贝叶斯优化器可能成为卡点
  • 早期没有可运行的东西验证
B

两阶段构建 ★ 推荐

Phase 1: 策略构建 + 回测（核心价值）→ Phase 2: 优化器 + 持仓管理

优点

  • Phase 1 完成后系统已可用
  • 早期验证 DSL 设计是否合理
  • 优化器基于真实回测引擎构建

代价

  • Phase 1 设计需提前预留扩展点
C

三阶段构建

Phase 1: 回测引擎（基础）→ Phase 2: AI 策略构建 → Phase 3: 优化器 + 持仓

优点

  • 先搞定最复杂的引擎
  • 每阶段目标清晰

代价

  • 前两个阶段都缺乏 AI 交互，体验不完整
  • 动力可能不足
