# Brainstorm Summary

- Change: add-ai-chat
- Date: 2026-07-08

## 确认的技术方案

采用无状态 Chat API + 后端即时聚合上下文方案。

- 新增独立 `/ai-chat` 页面和导航入口。
- 页面仅维护当前页面消息历史；刷新或重新打开后对话清空。
- 新增 `POST /api/ai-chat`，请求包含当前问题和本页临时消息历史。
- API 在服务端读取策略、未关闭持仓、最新可用价格、近期价格快照和少量记忆，构造 prompt 后调用 `CHAT` 场景 Anthropic 兼容模型。
- 模型只返回文本，可给出明确买入、卖出、加仓、减仓建议。
- 用户已确认 Chat 上下文应注入少量置顶/相关记忆。记忆作为投资偏好、复盘和背景信息注入，不得作为行情事实；需要控制数量和长度，避免旧笔记干扰判断。

## 关键取舍与风险

- 无状态 API 避免新增数据库表和迁移，符合临时对话范围；代价是每次请求都要重新读取上下文。
- 后端即时聚合上下文，避免信任客户端传入投资数据；代价是需要清晰控制查询范围和 prompt 大小。
- 记忆注入可提升回答个性化和背景理解；风险是旧笔记干扰判断，因此必须标记为背景信息并设置数量/字符上限。
- 价格快照不是实时行情；prompt 必须要求模型说明基于系统已有价格，不得声称实时价格。
- 明确交易建议存在误解风险；prompt 必须要求输出依据、风险和数据不足时的限制。

## 测试策略

- 单元测试覆盖 `CHAT` 模型配置回退、上下文构造、数据不足处理、记忆裁剪和记忆背景标记。
- API route 测试覆盖成功回答、空输入校验、临时历史传递、模型配置缺失、模型失败和数据不足行为。
- 页面测试覆盖发送问题、展示回答、追问时提交历史、错误展示、加载状态和刷新后清空对话。
- OpenSpec 校验覆盖 delta spec 格式和 change 有效性。
