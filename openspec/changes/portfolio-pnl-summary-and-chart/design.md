## Context

持仓管理页（`/positions`）目前按策略分组展示每只股票的当前持仓快照和浮动盈亏率，但缺少：
1. 跨策略聚合的「总持仓收益」摘要——用户需在脑中手动加总各策略盈亏
2. 收益率随时间的趋势视图——只有当前快照，无历史走势

系统已积累了每日 monitoring_run 的价格快照（`monitoringRuns.prices: jsonb`），可直接用于计算历史收益率，无需新的数据采集逻辑。

## Goals / Non-Goals

**Goals:**
- 持仓管理总览页顶部展示全量持仓汇总卡片（总成本、市值、绝对收益 $、收益率 %）
- 持仓管理总览页汇总卡片下方展示全量历史收益率折线图
- 策略详情页「持仓」Tab 顶部展示单策略历史收益率折线图
- 时间范围支持：1M / 3M / 全部 三档切换

**Non-Goals:**
- 实时价格拉取（继续沿用监控运行价格快照）
- 绝对收益（$）历史曲线图
- 多策略对比折线图
- 追踪 lot 历史变更（历史收益率使用当前 lots × 历史价格，这是已知的近似值）

## Decisions

### 1. 历史收益率使用「当前 lots × 历史监控价格」

**选择**：每个日期的收益率 = 当前 lot 成本 × 历史监控价格，而非记录 lot 的历史快照。

**理由**：lot 变更频率极低，近似误差可接受；追踪 lot 历史变更需要新的数据模型变更，复杂度不成比例。已在设计文档中明确列为 Non-Goal，用户已知悉。

### 2. 折线颜色基于最后一个数据点

**选择**：若最后一个数据点 `percentPnl >= 0`，线色为红色（`#dc2626`）；否则绿色（`#16a34a`）。整条线使用同一颜色。

**理由**：符合中国市场惯例（红涨绿跌）；单色线视觉简洁，避免分段着色的实现复杂度。

### 3. 共享 PnlChart 组件，通过 `fetchUrl` 接受数据源

**选择**：创建 `apps/web/components/pnl-chart.tsx`，Props 仅 `{ fetchUrl: string }`，组件自管理数据拉取和范围切换状态。

**理由**：两处集成（positions 页和策略详情页）仅 URL 不同，其余逻辑完全一致。fetchUrl 参数化避免重复组件，同时保持组件内聚（不需要父组件传数据）。

**备选**：父组件拉取数据、通过 `data` prop 传入图表。缺点：父组件需要额外的 range 状态和 fetch 逻辑，与 summary card 的现有 fetch 模式不一致。

### 4. 每日聚合取「同一策略该日最新一次运行」

**选择**：`GROUP BY runDate`，同一 `strategyId + runDate` 取 `createdAt` 最大的那条记录。

**理由**：偶发补跑可能在同一日产生多条记录，取最新一条最能代表当日最终状态。

### 5. 图表库选 Recharts

**选择**：`recharts ^2.15.0`。

**理由**：React 生态主流选择，React 19 兼容，API 声明式，`ResponsiveContainer` 内建支持响应式布局，`LineChart` 满足需求，无需额外封装。

## Risks / Trade-offs

- **历史准确性**：lot 变更后，变更日期之前的历史收益率会用变更后的 lot 重新计算，导致历史数据失真。→ 接受：已明确为 Non-Goal，数据量小、变更稀少，用户理解这是近似值。
- **空数据日期**：若某日期没有任何 position 有价格覆盖（`coveredCost === 0`），跳过该日期，折线图会出现断点。→ 接受：符合预期，已在 API 逻辑中明确处理。
- **Recharts 包体积**：约 200KB gzip，首屏加载增加。→ 接受：图表仅在用户主动访问持仓页时加载，可在后续按需考虑动态导入。
